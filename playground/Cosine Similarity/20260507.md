### 2. 코사인 유사도 공식 — 손글씨 검증

```
              A · B
cos(A, B)  =  ─────────────
              ‖A‖ × ‖B‖

           =  A₁B₁ + A₂B₂ + ... + AₙBₙ
              ─────────────────────────────────────────────
              √(A₁² + ... + Aₙ²) × √(B₁² + ... + Bₙ²)
```

용어 정리:
- **성분 (component)** = 벡터 안의 각 값. "원소(element)" 도 통용되지만 벡터 맥락에서는 성분이 표준
- **내적 (inner product / dot product)** = 대응 성분끼리 곱해서 합한 것
- **노름 (norm) = 1차원 절댓값의 다차원 확장 = 유클리드 거리** (1차 세션에서 도달한 통찰)

기호 구분:
- `·` (middle dot, U+00B7) — 벡터 내적
- `⋅` (dot operator, U+22C5) — 수학 정식, 입력 까다로움
- `×` — 스칼라 곱셈 또는 3D 벡터 외적 (cross product, 완전 다른 개념)

입력 방법:
- Windows: `Alt + 0183`, `Win + .`, 한글 IME `ㄱ + 한자키`
- Mac: `Option + Shift + 9`

### 3. 유사도 vs 거리 — sklearn API 와 직결

```
cosine similarity  =  (A · B) / (‖A‖ · ‖B‖)        범위 [-1, 1]   (1 = 같은 방향)
cosine distance    =  1 - cosine similarity         범위 [ 0,  2]  (0 = 같은 방향)
```

- `sklearn.metrics.pairwise.cosine_similarity` — 유사도 반환
- `sklearn.metrics.pairwise.cosine_distances` — 거리 반환
- `NearestNeighbors(metric='cosine')` — 내부적으로 **거리** 사용. 결과의 `distances` 가 작을수록 비슷한 것

수학 관례상 "거리(distance)" 는 0이 가까움 / 클수록 멀어짐. 클러스터링/최근접 이웃 알고리즘은 거리를 입력으로 받음.

### 4. sklearn 임포트 패턴 비교

```python
# 패턴 1 — 함수 1개만 쓸 때 (가장 짧음)
from sklearn.metrics.pairwise import cosine_similarity
cosine_similarity(X)

# 패턴 2 — 여러 함수 비교용 (네임스페이스 유지)
from sklearn.metrics import pairwise
pairwise.cosine_similarity(X)
pairwise.euclidean_distances(X)

# 패턴 3 — 풀 경로 (잘 안 씀)
import sklearn.metrics.pairwise
sklearn.metrics.pairwise.cosine_similarity(X)

# 패턴 4 — 종속성 운에 맡기는 위험 패턴
import sklearn.metrics                          # ⚠ 위험
sklearn.metrics.pairwise.cosine_similarity(X)   #    pairwise가 자동 import 됐는지 보장 X
```

**일반 규칙**: 상위 패키지 import 했다고 하위 서브모듈이 자동으로 따라오는 건 아님. 명시적 import 필수.

`sklearn.metrics` 안의 구조:
```
sklearn.metrics
├── (최상위)         → 모델 평가용 (accuracy_score, mean_squared_error)
└── pairwise         → 샘플 간 거리/유사도 (cosine_similarity, euclidean_distances, ...)
```

### 5. 데이터 준비 — 식별자 컬럼 처리

```python
cos_df = df.set_index('uni_cd')   # uni_cd 를 컬럼 → 인덱스로 이사
cos_df = cos_df.fillna(0)         # 결측 처리
```

**왜 set_index(uni_cd) 하나**: cosine_similarity 입력에서는 uni_cd 가 피처가 아니므로 빠져야 함. 다만 결과를 라벨링하려면 정보를 유지해야 하므로 `drop` 이 아닌 `set_index`.

**pandas index vs SQL index** (재정리):
- pandas index = **행의 이름표 (라벨)**, 항상 보임
- SQL index = 검색 보조 구조, 숨겨짐
- 접근 방법:
  - `cos_df['col']` → 컬럼 영역
  - `cos_df.index` → 인덱스 영역 (속성, 괄호 없음)

### 6. NaN 채우기 — `fillna` 의 정확한 문법

```python
# ❌ 잘못된 시도
cos_df.fillna(method=average)        # method= 는 ffill/bfill 용. average 는 정의 안 됨

# ✅ 평균/중앙값으로
cos_df = cos_df.fillna(cos_df.mean())     # Series 가 자동 매칭됨
cos_df = cos_df.fillna(cos_df.median())

# ✅ 컬럼별 다르게 (dict)
cos_df = cos_df.fillna({
    'gasoline': cos_df['gasoline'].mean(),
    'diesel':   0,
})

# ✅ sklearn 의 ML 파이프라인 표준
from sklearn.impute import SimpleImputer
imputer = SimpleImputer(strategy='mean')   # 'mean' / 'median' / 'most_frequent' / 'constant'
filled = imputer.fit_transform(cos_df)
```

**도메인 의미에 맞춰 선택**:
- 가격이 진짜 0 (안 팖) → `fillna(0)` ← 오늘 케이스
- 측정 누락 → 평균/중앙값
- outlier 많음 → 중앙값이 더 robust
- 시계열 → `ffill`/`bfill`

오늘 우리 데이터에서는 "고급휘발유 안 파는 주유소" 의 NaN 은 물리적으로 0이 맞음.

### 7. **매트릭스 → long format 변환** (오늘의 핵심)

```python
sim_wide = pd.DataFrame(
    cos_similarity,
    index   = cos_df.index,    # 행 라벨로 uni_cd
    columns = cos_df.index,    # 열 라벨로 uni_cd
)

sim_long = (
    sim_wide
    .stack()
    .rename_axis(['uni_cd_a', 'uni_cd_b'])      # 인덱스 단 이름 부여
    .reset_index(name='cos_similarity')         # 값 컬럼 이름 부여
)
```

**각 메소드의 분담**:

| 메소드 | 역할 | 영역 |
|---|---|---|
| `pd.DataFrame(arr, index=, columns=)` | numpy → DataFrame, 라벨 부착 | 양 축 라벨링 |
| `.stack()` | 컬럼을 인덱스로 쌓음 (가로→세로) | DataFrame → Series + MultiIndex |
| `.rename_axis([...])` | MultiIndex 단의 이름 부여 | 인덱스 영역 |
| `.reset_index(name=...)` | 인덱스 단을 컬럼으로, + 값 컬럼 이름 | 양쪽 다 처리 |

**타입의 여정**:
```
DataFrame (n×n)  →  Series (n², MultiIndex 2단)  →  DataFrame (n²×3)
```

`stack()` 직후가 **Series 인 이유**: 컬럼이 하나만 남으면 (값 컬럼) Series, 두 개 이상이면 DataFrame. pandas 의 본질적 구분.

---

### 8. **`reset_index` 의 진짜 정체** (오늘의 깨달음)

이름은 misleading. 실제 두 가지 일을 함:
1. 표면: 인덱스를 0,1,2,... 기본값으로 리셋
2. **실질**: 인덱스에 들어있던 라벨을 일반 컬럼으로 끌어내림 ← 우리가 원하는 것

`Series.reset_index(name='X')` 만의 트릭: **`name=` 으로 값 컬럼 이름까지 한 방에**. DataFrame 의 reset_index 에는 `name=` 없음.

→ stack() 결과(Series) 에서 바로 쓸 수 있는 강력한 1행 변환.

### 9. **Index 객체 공유 함정** (오늘 부딪힌 큰 버그)

```python
# 함정 코드
sim_wide = pd.DataFrame(
    cos_similarity,
    index   = cos_df.index,   # 같은 객체 ──┐
    columns = cos_df.index,   # 같은 객체 ──┴── 양쪽이 같은 Index 참조
)

sim_wide.index.name   = 'uni_cd_a'   # 양쪽 다 'uni_cd_a' 가 됨
sim_wide.columns.name = 'uni_cd_b'   # 양쪽 다 'uni_cd_b' 가 됨
# → 결과: 행/열 양쪽 다 'uni_cd_b' → stack→reset_index 충돌

# 에러 메시지
ValueError: cannot insert uni_cd_b, already exists
```

**해법 (정공법)**: 인덱스 직접 안 건드리고 stack 결과의 MultiIndex 만 다루기.
```python
sim_long = (
    sim_wide
    .stack()
    .rename_axis(['uni_cd_a', 'uni_cd_b'])      # 별도 객체에 이름 부여
    .reset_index(name='cos_similarity')
)
```

**대안**: `pd.Index(cos_df.index, name='uni_cd_a')` 로 새 Index 객체 만들어서 분리.

### 10. Boolean 마스크 필터링 — SQL WHERE 의 pandas 버전

```python
# ❌ 비교만 하고 끝남 (Boolean Series 만 만들고 DataFrame 못 받음)
sim_clean = sim_long['uni_cd_a'] < sim_long['uni_cd_b']
# 결과: True/False 만 있는 Series

# ✅ 필터링까지
sim_clean = sim_long[sim_long['uni_cd_a'] < sim_long['uni_cd_b']]
#                   ↑ 이 대괄호가 WHERE 역할
```

**비유**: Boolean Series 는 "손전등 비출 곳" 결정, `df[mask]` 는 "실제로 비춤".

**`<` 트릭** — 자기쌍 + 중복쌍 한 방에 제거:
- `'A' < 'A'` → False (자기쌍 제거)
- `'A' < 'B'` → True (남음)
- `'B' < 'A'` → False (중복 제거)

SQL self-join 의 `WHERE a.id < b.id` 와 동일한 패턴.

행 수 변화:
- 원본 long: `n²`
- 자기쌍 제외: `n² - n`
- 중복까지 제외 (`<` 필터): `n(n-1)/2`

오늘 데이터: 10298 주유소 → 약 1억 행 → 약 5천 3백만 행.

### 11. `sort_values` 와 `ascending=False`

```python
# ❌ 자주 만나는 타이포
.sort_value(by=...)              # value 단수 — 없는 메소드
.sort_values(by='cos_similiarity')   # similarity 스펠링

# ✅
.sort_values(by='cos_similarity', ascending=False)
```

**pandas 의 정렬 메소드명은 복수형**: `sort_values`, `drop_duplicates`, `reset_index`. 값 여러 개 / 중복 여러 개 / 인덱스 여러 개를 다루므로 복수.

**`descending=` 파라미터는 없음**. `ascending=True/False` 하나만 사용.

다만 다중 컬럼 정렬에서 컬럼별 방향 다르게 가능:
```python
df.sort_values(
    by       =['a', 'b', 'c'],
    ascending=[False, True, False],
)
```

**디버깅 팁**: Jupyter Tab 자동완성으로 메소드명/컬럼명 오타 90% 예방 가능.

### 12. 결과 해석 — 0.491398 가 동률로 나온 미스터리

증상: 전체 top 20 sort 했더니 모두 정확히 `0.491398` 이고 대부분 A0010118 이 포함됨.

원인:
- 1차 세션에서는 `where 모든 가격 not null` 로 깨끗한 주유소만 사용 → 0.999... 가 자연스러움
- 오늘 SQL은 `where gasoline is not null` 만 → NaN 다수 → `fillna(0)` 적용
- **결측 패턴이 같은 주유소들 사이에서 코사인 값이 동률(tie)** 로 떨어짐
- `head(20)` 이 동률 중 우연히 처음 20개를 뽑은 것

교훈:
- 0 으로 채우는 게 도메인적으로 맞을 때도 있고, 코사인 계산에는 왜곡 요인이 되기도 함
- 결측 패턴 자체가 코사인 결과의 신호처럼 작용할 수 있음
- 차원에 0 이 박히면 그 차원에서는 비교 자체가 무의미해짐 (벡터 길이 줄어듦)

### 13. "한 주유소의 top 20" vs "전체 top 20" — 다른 쿼리

| 의도 | pandas 패턴 | SQL |
|---|---|---|
| 전체 top 20 쌍 | `<` 필터 + sort + head | `WHERE a<b ORDER BY ... LIMIT 20` |
| 한 주유소의 top 20 | `==` 필터 + sort + head (자기쌍만 제외한 양방향 long 사용) | `WHERE a='X' ORDER BY ... LIMIT 20` |
| 각 주유소의 top 20 | `groupby + head(20)` | `ROW_NUMBER() OVER (PARTITION BY a) <= 20` |

한 주유소 기준 패턴:
```python
sim_long_full = sim_long[sim_long['uni_cd_a'] != sim_long['uni_cd_b']]
                          # 자기쌍만 제외, 양방향 다 살아있음

target = 'A0000004'
top20 = (
    sim_long_full[sim_long_full['uni_cd_a'] == target]
    .sort_values('cos_similarity', ascending=False)
    .head(20)
)
```

`<` 필터는 자기쌍+중복 둘 다 제거하지만, 한 주유소 입장에서 보려면 그 주유소가 양쪽 어디든 등장해야 함 → `!=` 필터로 변경.

## 🤔 다음 단계 (내일)

### 3번 — `sklearn.neighbors.NearestNeighbors`

매트릭스 안 만들고 처음부터 long-ish format 으로 top-K 이웃을 받는 정공법.

```python
from sklearn.neighbors import NearestNeighbors

nn = NearestNeighbors(n_neighbors=20, metric='cosine')
nn.fit(X)
distances, indices = nn.kneighbors(X)

# distances: shape (n, k)   - 각 행의 top k 이웃 거리
# indices:   shape (n, k)   - 그 이웃들의 원본 인덱스 위치
```

매트릭스 N×N (1억 셀) 대신 **N×K (20만 셀)** 만 메모리에 올림. 시간도 훨씬 빠름.

**주의**: 결과는 `distances` (작을수록 가까움). 유사도로 보려면 `1 - distance` 변환.

### 4번 — 순수 SQL self-join

회사 환경(Spark/Hive) 에서도 통하는 보편 패턴.
```
CTE 1: norms (id, sqrt(sum(v²)))
CTE 2: dot   (id_a, id_b, sum(a.v * b.v))  with id_a < id_b
SELECT dot / (norm_a * norm_b)
```

DuckDB 한정 보너스: `list_cosine_similarity(arr1, arr2)` 한 줄로 끝.

## 💡 오늘의 큰 깨달음

1. **에러 메시지는 정직하다**. `cannot insert uni_cd_b, already exists` 같은 메시지가 정확히 원인을 알려줌. 영어 그대로 읽는 습관이 디버깅 시간을 1/3 로 줄임.
2. **메소드 이름이 misleading 한 경우 있음**. `reset_index` 는 진짜 일이 "인덱스 → 컬럼 이전" 이라는 부산물. `sort_values` 가 복수형인 이유도 처음 보면 의외.
3. **pandas 의 양면성**: 강력하지만 SQL 머리와 충돌하는 지점이 많음. 인덱스/컬럼 이중 구조, 객체 공유 함정, 메소드 명명 규칙 등.
4. **반복이 답**. `fillna` 같은 함수는 한 번 보고 다음 셀에서 안 물어보고 떠올린 것 → 이게 진짜 성장. (오늘 본인이 본인 칭찬한 모먼트)
5. **데이터 결측 처리는 모델 결과를 좌우한다**. `fillna(0)` 이 도메인적으로 맞아도, 코사인 계산에선 벡터 차원을 죽이는 효과가 있음. 0.491398 동률 사건이 그 증거.
6. **올바른 쿼리를 짜는 게 절반**. "전체 top 20" 과 "한 주유소의 top 20" 은 완전히 다른 SQL. pandas 도 마찬가지.
