## 📚 학습 정리

### 1. 학습 계획 정비 — `study_plan.md` 신설

cosine 다음 학습 순서를 흩어진 머릿속에서 한 곳으로:

```
🟢 진행 중: Cosine Similarity 5단 플랜 (3번 진행 중)
🔵 다음 큐:
   1. Spearman → Pearson (상관계수 패밀리)
   2. Chi-square (χ²) 검정 — 범주형 독립성
   3. Jaccard 유사도 — 집합 기반
   4. Cox PH — 생존 분석
   5. Lasso / Ridge / Elastic Net — 정규화 회귀
```

**오늘 새로 추가한 통찰**: `Pearson(X, Y) = cosine_similarity(X-mean, Y-mean)`. **중심화한 두 벡터의 cosine = Pearson 상관계수**. 그래서 cosine 다음에 Pearson 을 두는 게 자연스러운 흐름. 분자가 공분산, 분모가 표준편차의 곱. 같은 골격, 평균을 뺀 것만 다름.

→ 이 사실이 박히면 나중에 Lasso/Ridge 의 `‖β‖₁`, `‖β‖₂²` 같은 페널티 항도 "그 노름이구나" 하고 자연스럽게 들어옴.

### 3. 공식 문서의 **위임 패턴** — 가장 큰 메타 깨달음

`metric` 파라미터 설명에서 본 문장:

이 문장을 처음엔 "cosine 이 안 보이네" 로 잘못 해석. 진짜 의미는:

> "**가능한 값 목록은 이 페이지에 인라인으로 안 적어놨어요. 두 군데 참조 가서 보세요.**"

→ 거의 모든 라이브러리 문서가 이래요. 다 나열하면 페이지가 너무 길어져서 다른 곳으로 위임. 이런 표현 만나면 **"여기 안 적힌 게 있다"** 는 신호:

```
"See documentation of X for ..."
"Valid values are listed in ..."
"Refer to Y for full options"
"See also ..."
```

문서 다 인라인으로 들어있다고 가정하면 안 됨. 클릭하든, 코드로 호출해서 확인하든, 실험해서 검증하든 — **추가 행동 필요한 시점.**

### 4. sklearn 의 **Estimator 패턴** — 평생 자산

오늘의 가장 큰 자산. **모든** sklearn 모델 (LinearRegression, KMeans, RandomForest, ...) 에 동일하게 적용:

```
1. 설정만 먼저 만든다       → model = ClassName(parameters)
2. 그 다음 데이터를 학습     → model.fit(X)
```

`.fit()` 이 동시에 두 가지 일을 함:
- **(side effect)** model 객체 자체를 변형 (학습된 상태로)
- **(return)** 자기 자신(`self`) 을 반환

그래서 다음 세 가지 형태가 다 같은 결과:

```python
# 1. 한 줄 체인 (가장 흔한 관용구)
nn = NearestNeighbors(n_neighbors=20, metric='cosine').fit(cos_df)

# 2. 두 줄, 반환값 무시 (똑같이 작동)
nn = NearestNeighbors(n_neighbors=20, metric='cosine')
nn.fit(cos_df)

# 3. 두 줄, 반환값 받기 — 변수만 늘어남 (잉여)
nn = NearestNeighbors(n_neighbors=20, metric='cosine')
nn_df = nn.fit(cos_df)        # nn is nn_df → True
```

### 5. **pandas 와 sklearn 의 정반대 철학**

pandas 의 머리로 sklearn 을 쓰면 헷갈리는 지점:

| | pandas | sklearn |
|---|---|---|
| 메소드 호출 시 | **새 객체 반환** (원본 불변) | **원본 변형 + self 반환** |
| 예시 | `df2 = df.fillna(0)` → df 안 변함 | `nn.fit(X)` → nn 자체가 학습됨 |
| 결과 받는 법 | 반환값 받아야 함 | 받아도 되고 안 받아도 됨 |

이거 알면 sklearn 코드 읽기 한 단계 도약.

### 6. `algorithm` vs `metric` — 직교하는 두 파라미터

오늘 만난 첫 에러:

```
InvalidParameterError: The 'algorithm' parameter of NearestNeighbors 
must be a str among {'kd_tree', 'ball_tree', 'brute', 'auto'}. 
Got 'cosine' instead.
```

처음엔 "cosine 이라는 방법이 없나봐" 로 잘못 해석. 에러는 **파라미터 이름까지 콕 찍어서** "**algorithm 자리는 잘못됐다**" 라고만 말함. cosine 자체가 없다는 게 아니라 **algorithm 이 받는 값이 아니라는** 것.

| 파라미터 | 무엇을 정하는가 | 가능한 값 |
|---|---|---|
| **`algorithm`** | 어떻게 찾을지 (검색 전략·자료구조) | `kd_tree`, `ball_tree`, `brute`, `auto` |
| **`metric`** | 뭘로 잴지 (거리/유사도 공식) | `euclidean`, `cosine`, `manhattan`, ... |

비유: SQL 의 JOIN 에서 "어떤 컬럼으로 매치 (공식)" 와 "내부적으로 hash/merge/nested loop 어떤 거로 찾을지 (검색 전략)" 가 다른 차원인 것과 같음.

### 7. **Minkowski 거리** — 거리의 일반화

`metric` default 가 `'minkowski'` 인 이유:

```
Minkowski(A, B, p) = ( Σ |aᵢ - bᵢ|^p ) ^ (1/p)
```

| p 값 | 이름 | 의미 |
|---|---|---|
| p = 1 | Manhattan (cityblock) | 가로·세로 그리드 거리 |
| p = 2 | Euclidean | 직선 거리 (= 노름) |
| p → ∞ | Chebyshev | 가장 큰 차원 차이만 |

파라미터 `p` 하나만 바꿔도 Manhattan ↔ Euclidean 사이 자유 이동. "거리의 일반화된 정의" 라서 default 로 들어가있음. sklearn 의 minkowski + p=2 = 결국 Euclidean.

오늘 만난 모든 에러가 정확히 무엇이 잘못됐는지 알려줌:
- "algorithm 자리에 cosine 못 와요. {목록} 만 가능"
- "NearestNeigbors 라는 이름 없음" (타이포)
- 등등

영어 그대로 천천히 읽으면 답이 거기 있음. 의역하지 말고 **literal 하게** 읽기.

### 9. `nn` 의 정체 — 데이터가 아니라 **학습된 객체**

오늘 받은 가장 좋은 질문: *"nn 은 df 야 객체야?"*

→ **객체**. 정확히는 `NearestNeighbors` 클래스의 **인스턴스**. DataFrame 아님.

| sklearn 세계 | DB 세계 |
|---|---|
| `cos_df` (DataFrame) | 테이블 |
| `NearestNeighbors(...)` (학습 전) | 준비된 인덱스 정의 (CREATE INDEX 구문만 짜둔 상태) |
| `.fit(cos_df)` 호출 | CREATE INDEX 실행 |
| `nn` (학습 후) | **인덱스가 빌드된 검색 엔진** |
| `.kneighbors(X)` | 인덱스 lookup 쿼리 |

학습 후 `nn` 안에 들어있는 것들 (직접 찍어볼 수 있음):

```python
nn.n_samples_fit_     # 학습한 샘플 수 → 10298
nn.n_features_in_     # 각 샘플의 차원 → 가격 컬럼 수
nn.feature_names_in_  # 컬럼 이름들
nn.effective_metric_  # 실제 사용된 metric → 'cosine'
nn._fit_X             # 내부 저장된 학습 데이터의 numpy 버전
```

**끝에 언더스코어 붙은 속성** (`n_samples_fit_`, `coef_`, `labels_`, ...) 은 sklearn 관용 — **"학습 후에만 생기는 결과 속성"** 표식. 이거 한 번 박아두면 앞으로 모든 sklearn 모델에서 통함.

### 10. `kneighbors()` 의 반환값 — 두 개의 짝꿍 배열

```python
distances, indices = nn.kneighbors(cos_df)
# 둘 다 shape (10298, 20) — N×K
```

머릿속에 박을 그림:

```
distances (10298 × 20)                  indices (10298 × 20)

        이웃1  이웃2 ... 이웃20             이웃1  이웃2 ... 이웃20
주유소0 [0.000  0.003 ... 0.012]     [   0   7234 ...  4501]
주유소1 [0.000  0.001 ... 0.015]     [   1    445 ...  2103]
주유소2 [0.000  0.005 ... 0.018]     [   2   8893 ...  6755]
...                                  ...
```

- 행 = "한 주유소"
- 열 = "그 주유소의 몇 번째 가까운 이웃"
- 0번 열은 항상 자기 자신 (거리 0)
- `distances[i][j]` 와 `indices[i][j]` 는 **좌표 짝꿍**

⚠ `distances` 는 **거리**지 유사도가 아님. 0이 가까움, 클수록 멀어짐. 유사도로 환산하려면 `1 - distance`.

### 11. **numpy 트릭 3종 세트** — 오늘의 핵심 도구

#### ① `.flatten()` — 2D → 1D 평탄화

```
indices (10298, 20):
[[ 0, 7234,  882, ...,  4501],     ◀ 0번 주유소의 이웃 20개
 [ 1,  445, 9221, ...,  2103],     ◀ 1번 주유소의 이웃 20개
 ...]

         │ flatten()
         ▼

indices.flatten() (205960,):
[ 0, 7234, 882, ..., 4501,  1, 445, 9221, ..., 2103,  ...]
  └────0번 이웃 20개───┘  └────1번 이웃 20개───┘  ...
```

**왜 평탄화 필요?** → DataFrame 컬럼은 1차원이어야 하니까.

#### ② `.repeat(k)` — 각 원소를 k 번씩 늘리기

```
cos_df.index:           ['A', 'B', 'C', ...]            (10298개)
cos_df.index.repeat(20): ['A','A','A',...,'B','B','B',...,'C','C',...]
                                                         (205960개)
```

`uni_cd_a` 컬럼 만들 때 각 주유소가 20번씩 등장해야 하니까.

#### ③ Fancy Indexing — 위치 배열로 vectorized lookup

오늘의 진짜 새 개념. **숫자 배열을 또 다른 배열의 인덱스로 쓸 수 있음**:

```python
arr = np.array(['A', 'B', 'C', 'D', 'E'])
positions = np.array([0, 2, 4, 0, 3])
arr[positions]       # array(['A', 'C', 'E', 'A', 'D'])
```

positions 안의 각 숫자가 차례차례 arr 의 자리번호로 사용되고, 그 자리의 값들이 같은 순서로 모아져 새 배열로 반환됨.

본인 데이터에 적용:

```python
cos_df.index.values     # 길이 10298 마스터 배열
indices.flatten()       # 길이 205960 위치 번호 배열 (0~10297)

cos_df.index.values[indices.flatten()]
# → 길이 205960 uni_cd 배열. 각 위치번호 → 실제 uni_cd 로 변환됨.
```

**SQL 비유**:

```sql
SELECT m.uni_cd
FROM   master_uni_cd  AS m
JOIN   positions_list AS p
       ON m.row_position = p.position
ORDER BY p.original_order
```

= "**위치 번호 배열로 마스터 테이블에서 vectorized lookup**". for loop 대신 numpy 가 한 방에 처리.

### 12. **`.stack()` vs `.flatten()`** — 사촌이지만 동네가 다름

| | `.stack()` | `.flatten()` |
|---|---|---|
| **소속** | pandas | numpy |
| **입력** | DataFrame (라벨 있음) | ndarray (라벨 없음) |
| **출력** | Series (MultiIndex 로 라벨 보존) | 1D ndarray |
| **라벨 운명** | 따라옴 | 사라짐 |

**값의 순서는 같음** (행 단위로 좌→우, 위→아래). 차이는 오직 **라벨이 따라오느냐**.

| pandas/numpy | SQL |
|---|---|
| `.stack()` | `UNPIVOT` (컬럼명을 새 컬럼으로 보존) |
| `.flatten()` | (SQL 에 직접 대응 없음. 거친 평탄화) |

오늘 케이스에서 `.flatten()` 을 쓴 이유: sklearn 의 `kneighbors()` 가 **numpy 배열** 을 반환하기 때문. 라벨이 애초에 없는 상태로 시작해서 보존할 게 없음.

### 13. **본인의 정직한 자가진단** — "오히려 더 어렵게 느껴진다"

세션 마지막에 본인 입에서 나온 말. **정확한 메타인지**.

이유:

| | 5/7 (cosine_similarity + stack) | 오늘 (NearestNeighbors) |
|---|---|---|
| 사용 세계 | pandas 한 동네 | pandas ↔ numpy 두 동네 |
| 라벨 운명 | 매 단계 자동 보존 | numpy 추락 → 별도 lookup 으로 복구 |
| 새 개념 | stack/reset_index | Estimator 패턴, fancy indexing, repeat, flatten |
| 인지 부담 | 한 가지 사고 모드 | 두 사고 모드 + 다리 |

오늘 코드 안에서 머릿속이 **pandas → numpy → numpy → pandas** 네 번 점프. 점프마다 라벨 사라졌다 붙었다 하면서 사고 비용 누적.

### 14. **직관성 vs 확장성 트레이드오프** — 메타 원리

```
5/7  방식 : 직관적이지만 N×N (1억 셀) 매트릭스 통째로
오늘 방식 : 어렵지만 N×K (20만 셀) — 500배 절약
```

10298 주유소는 둘 다 어찌어찌 됨. 하지만:
- 50,000개 → 1억 → 25억 셀. 5/7 방식은 메모리 폭발
- 카드 거래 수백만 건 → 5/7 방식은 시도 자체 불가능

SQL 비유:
- **5/7 방식** ≈ `SELECT *, computed_col FROM table` → 다 만들고 필터
- **오늘 방식** ≈ 인덱스 + `WHERE` + `LIMIT` → 처음부터 필요한 것만

전자가 직관적이지만 큰 테이블에선 죽고, 후자가 인지 비용은 높지만 어디서든 통함. 같은 패턴이 데이터 분석 전반에 반복됨.

## 🎁 오늘 최종 코드

```python
from sklearn.neighbors import NearestNeighbors

cos_df = df.set_index('uni_cd')
cos_df = cos_df.fillna(0)

# 1단계: 설정 + 학습
nn = NearestNeighbors(n_neighbors=20, algorithm='auto', metric='cosine')
nn.fit(cos_df)

# 2단계: 답 받아오기 — 두 개의 numpy 배열
distances, indices = nn.kneighbors(cos_df)
n, k = distances.shape   # 10298, 20

# 3단계: long format DataFrame 으로 펼치기
cos_long = pd.DataFrame({
    'uni_cd_a':       cos_df.index.repeat(k),                 # 각 uni_cd 를 20번씩
    'uni_cd_b':       cos_df.index.values[indices.flatten()], # 위치 → uni_cd lookup
    'cos_similarity': 1 - distances.flatten(),                # 거리 → 유사도
})

# 4단계: 자기쌍 제거 (top-1 은 항상 자기, distance=0)
cos_long = cos_long[cos_long['uni_cd_a'] != cos_long['uni_cd_b']]
```

행 수: `10298 × 19 = 195,662`.

**5/7 의 53,000,000 행짜리 결과와 비교** — 같은 사용 가능 정보 (각 주유소의 top 이웃) 를 270배 적은 메모리로.

## 💡 오늘의 큰 깨달음

1. **공식 문서의 위임 패턴**: "See documentation of X" 류 문장은 "여기 안 적힌 게 있다" 는 신호. 클릭/실험 필수.

2. **sklearn Estimator 패턴은 평생 자산**: `Class(...).fit(X)` 형식 + `.fit()` 이 mutate + return self. 이후 모든 sklearn 모델에 동일.

3. **에러 메시지는 파라미터 이름까지 콕 찍는다**: "algorithm 자리에 cosine 못 와요" 와 "cosine 자체가 없어요" 는 완전히 다른 메시지. literal 하게 읽기.

4. **numpy fancy indexing 의 위력**: 위치 배열로 한 방에 vectorized lookup. for loop 보다 훨씬 빠름. 데이터 분석 전반에 두루 쓰임.

5. **`.stack()` vs `.flatten()` 의 핵심 차이는 라벨**: 값의 순서는 같음. 라벨이 따라오느냐 사라지느냐가 갈림길. pandas 와 numpy 의 철학 차이를 압축.

6. **pandas vs sklearn 의 정반대 철학**: pandas 는 새 객체 반환, sklearn 은 원본 mutate + self 반환. 이거 모르면 sklearn 코드 헷갈림.

7. **직관성 vs 확장성 트레이드오프는 곳곳에 반복**: 데이터 사이즈가 커지면 직관적인 도구가 죽음. 인지 비용을 감수하고 효율적 도구를 익히는 게 실무 무기.

8. **본인의 자가진단 — "어렵게 느껴진다"**: 정직한 메타인지. 두 라이브러리 사이 점프하는 비용이 있었음을 정확히 짚음. 어려움을 회피하지 않고 끝까지 따라온 게 오늘의 가장 큰 수확.

9. **Pearson 의 정체**: `Pearson = cosine_similarity(중심화한 두 벡터)`. cosine 다음 학습 토픽으로 자연스러운 연결.
