## 📚 학습 정리

### 1. 함수(SQL) vs 메서드(pandas) — `pd.corr(a,b)`가 안 되는 이유

`AttributeError: module 'pandas' has no attribute 'corr'`.

```
SQL :   corr(gasoline, diesel)        동사(목적어1, 목적어2)   — 함수형
pandas: df['gasoline'].corr(df['diesel'])   주어 . 동사(목적어)  — 객체지향
```

- pandas엔 공중에 뜬 `corr` 함수가 없다. `corr`은 **컬럼(Series)이 가진 기능(메서드)**.
- 객체(object) = "데이터 + 그 데이터가 할 줄 아는 동작들"을 한 덩어리로 묶은 것. 그래서 명사(데이터)가 동사를 품고 다니며 문장의 **주어** 가 된다.
- **한 줄**: 점(`.`) 앞에 데이터(주어), 점 뒤에 그 데이터가 품은 동작.
- 단, 파이썬은 순수 객체지향이 아님 — `len(df)`(함수형)와 `df.head()`(객체형)가 공존. SQL도 틀린 게 아니라 *선언형* 이라는 다른 패러다임.

### 2. 따옴표 = 값 / 따옴표 없음 = 이름·타입

`df['part_dt'].astype(str)` 에서 `str`에 따옴표가 없는 이유.

| 표기 | 정체 |
|---|---|
| `'part_dt'` (따옴표 O) | 텍스트 값(데이터) |
| `str` (따옴표 X) | 파이썬 내장 타입의 *이름* |

- `cast(x as STRING)` 의 STRING도 따옴표 안 침 → 같은 이치. `cast(x as STRING)` ↔ `x.astype(str)`.

### 3. `.str` accessor — 셀 안 텍스트로 들어가는 손잡이

```
df['part_dt'][:4]       → 앞 4개 '행'을 자름      (컬럼 구조를 자름)
df['part_dt'].str[:4]   → 각 값의 앞 4'글자'      (셀 안 텍스트로 들어감)
```

- `.str` = "이 컬럼을 글자로 보고, 다음 동작을 각 칸마다 적용해". 형제로 `.dt`(날짜), `.cat`(범주형).

### 4. 슬라이스 — 음수는 "뒤에서"

```
[:4]   앞 4글자       ↔  SQL LEFT(x, 4)
[-4:]  뒤 4글자       ↔  SQL RIGHT(x, 4)
[4:]   4번부터 끝까지 (위치 기준, "뒤 4개"와 우연히 같아 보일 뿐)
```

- "뒤에서 N개"는 길이 무관하게 `[-N:]` 가 안전.

### 5. groupby + apply + lambda — 그룹별 corr의 핵심

```python
df.groupby('yyyy').apply(lambda y: y['disel_prc'].corr(y['gasoline_prc']))
```

- `df.groupby('yyyy')` = SQL `GROUP BY yyyy`. 주어(df) 고정 → 동사(groupby)에 "by 무엇"만 소괄호로.
- `lambda y: ...` = 이름 없는 일회용 함수. `y`는 **빈칸(placeholder)**, 채우는 건 `apply`.
- `apply`는 연도별 미니테이블을 하나씩 꺼내 `y`에 꽂고 lambda를 반복 호출.
- **`y` = 현재 그룹 / `df` = 안 변하는 전체.** 안에서 `df`를 쓰면 그룹을 무시 → 모든 해가 똑같은 통짜 값(버그의 신호: "모든 그룹 값이 동일 = 그룹 변수 안 씀").
- SQL이 뒤에서 몰래 처리하던 "현재 그룹"을, pandas는 `y`로 명시적으로 드러냄.

### 6. 파이썬 컨테이너 지도

| 쓰면 | 정체 | 성격 | SQL 비유 |
|---|---|---|---|
| `[1,2,3]` | list | 순서O, 수정O, 중복O | 줄 선 값들 |
| `(1,2,3)` | tuple | 순서O, 수정X(고정) | 안 바뀌는 한 줄 |
| `{1,2,3}` | set | 순서X, 중복 제거 | `DISTINCT` |
| `{'a':1}` | dict | key→value | 컬럼명:값 / 룩업 |

- **기호 이중 역할**: `[]` list/꺼내기, `()` tuple/호출, `{}` set·dict(콜론 있으면 dict).
- 점+동사면 호출 `()`, 변수 뒤 바로면 꺼내기 `[]`.

### 7. Series vs DataFrame

- **Series = 컬럼 하나(1D)**, **DataFrame = 표 전체(2D)**. DataFrame = Series 여러 개를 옆으로 붙인 것.
- `df['x']` → Series, `df[['x','y']]` → DataFrame(이중 대괄호 안쪽은 컬럼명 list).
- `yearly_corr`이 Series로 나온 이유: 연도마다 값 하나씩 = 1D. `.reset_index()` 로 yyyy를 컬럼으로 끌어내면 2D DataFrame으로 승격.

### 8. 컬럼명 정리 — rename vs columns=

```python
.rename(columns={0: 'corr'})       # 부분 수정 — 지정한 것만. 정수 0(따옴표X) 주의
.columns = ['year', 'corr']        # 전체 교체 — 전부 적어야, 순서대로
```

- 값 컬럼이 `0`(정수)이 된 이유: Series에 `.name`이 없어 reset 시 자동 번호 부여.
- rename은 새 표를 반환(`x = x.rename(...)`), `.columns=`는 그 자리에서 변경.

## 🎁 오늘 코드 (최종)

```python
# A4. 연도별 corr — pandas 버전
import pandas as pd
df['yyyy'] = df['part_dt'].astype(str).str[:4]

yearly_corr = (
    df.groupby('yyyy')
      .apply(lambda y: y['disel_prc'].corr(y['gasoline_prc']))
      .reset_index()
      .rename(columns={0: 'corr'})
)
display(yearly_corr)
```

→ 결과는 5/13 SQL A2와 동일: 2022=0.708, 2023=0.563(전쟁 충격), 2025~2026 회복.

## 💡 오늘의 큰 깨달음

1. **에러는 개념의 입구** — `ParserException`(SQL 문법), `AttributeError`(메서드 vs 함수), `.df()` 오용(DuckDB 식구 vs pandas 식구). 빨간 줄 첫 단어가 원인의 절반을 알려줌.

2. **파이썬은 영문법** — SQL=동사중심(함수), pandas=주어중심(주어.동사). "객체지향"이라는 추상어의 실체가 이 한 줄. `df.groupby('yyyy')` = "df야, yyyy로 묶어" 로 그대로 읽힘.

3. **`y` vs `df`** — apply가 채워주는 빈칸 `y`를 받아써야 그룹별로 돈다. SQL이 숨긴 "현재 그룹" 톱니바퀴를 손으로 돌리는 경험.

4. **암기가 아니라 모델** — 함수 이름(reset_index, rename...)은 휘발성. 안 까먹는 건 Series/DataFrame, SVO, 컨테이너, y vs df 같은 구조. 시니어도 `pandas rename column` 검색함. LLM 시대엔 더더욱 문법 암기 가성비 낮음.

5. **SQL 우선 + pandas 핸드오프** — "SQL이 10배 쉽다"는 본능은 게으름이 아니라 좋은 판단. 무거운 표 작업은 SQL/DuckDB로 끝내고, pandas는 SQL이 못 하는 것(시각화·ML)에만. `con.sql(...).df()` 가 그 핸드오프 지점. 이게 업계 best practice.

6. **데이터는 살아있다** — 같은 쿼리인데 5/13 전체기간 corr(0.99153)과 6/1 값(0.99257)이 다름. NAS 파이프라인이 보름치를 더 부어서. 숫자는 고정이 아니라 흐름.
